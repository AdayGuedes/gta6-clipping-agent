# Sesión 2026-11-19 · Fase 3 · Juez LLM tras una interfaz (Gemini, tier gratuito)

## Qué se hizo

- D12 en `docs/DECISIONS.md`: el juez va tras una interfaz `Judge` y Gemini en
  tier gratuito es el primer proveedor. SPEC §3, §5, §7, §7.2 y §8, la
  restricción 4 y la pila de CLAUDE.md, y el README pasan a lenguaje de
  proveedor neutro.
- Dependencias: `google-genai>=3,<4` y `python-dotenv>=1,<2`. `.env.example`
  lista `GEMINI_API_KEY` y `GEMINI_MODEL` (sin valores) en lugar de
  `ANTHROPIC_API_KEY`.
- `src/timeparse.py`: `seconds_to_hhmmss`, que trunca a segundos enteros.
- `src/judge.py`:
  - `Judgment` (pydantic, `extra="forbid"`): `start_s`, `end_s` (mayor que
    `start_s`), `category` de la lista cerrada, `hook` no vacío y las tres
    puntuaciones del juez (0-25, 0-25, 0-20).
  - `Judge` (Protocol): `judge(candidate, segments) -> Judgment`.
  - `JudgeError` y `JudgeConfigError` (falta `GEMINI_API_KEY`).
  - `build_prompt`: rúbrica, ventana, datos del chat ya calculados por código,
    transcripción con marcas de tiempo, categorías cerradas, gancho en español
    de 12 palabras como máximo y la transcripción tratada como datos.
  - `GeminiJudge`: carga `.env` con `load_dotenv()`, pide salida JSON con
    `response_json_schema` y valida la respuesta con `Judgment`. Acepta un
    cliente inyectado; el modelo sale del argumento, de `GEMINI_MODEL` o de
    `gemini-3.8-flash`.
  - Contadores `calls`, `input_tokens` y `output_tokens` (candidatos más
    pensamiento) acumulados desde `usage_metadata`; una llamada cuenta aunque
    el SDK falle.
  - `segments_in_window`, `round_half_up` y `judge_candidates`, que cortan la
    transcripción por candidato, reintentan una vez, ensamblan el `Moment`,
    deduplican por solape y devuelven como máximo 5 momentos.
- Decisiones fijadas con el arquitecto:
  - Una colisión por truncado (inicio y fin iguales al pasar a segundos
    enteros) es un `Moment` inválido y se reintenta.
  - El solape es estricto: dos momentos que solo se tocan se mantienen ambos.
  - Un error de la API cuenta como intento fallido, sin espera entre intentos.
  - Un candidato sin transcripción en la ventana se descarta sin llamar al
    juez y se registra el motivo.
  - El reintento repite la llamada sin pasar el error anterior, así que la
    SPEC §8 se ajustó.

## Reparto del trabajo

D12, los cambios de SPEC, CLAUDE.md y README, `seconds_to_hhmmss` y un primer
borrador de `src/judge.py` se escribieron con Claude Sonnet 5.5. A mitad de la
fase el usuario pidió implementar el código con Opus 5.5 y delegar tests y
documentación en un subagente Sonnet 5.5 con esfuerzo alto: Opus revisó y
dejó la versión final de `src/judge.py`, y el subagente escribió
`tests/test_judge.py`, el arreglo del test de la fase 0 y estos documentos.

## Tests

`ruff check .` sin avisos, `black --check .` sin cambios pendientes y
`python -m pytest` con 272 passed. `tests/test_judge.py` aporta 71 tests, todos
sin red: un fixture automático anula `load_dotenv`, hace que construir el
cliente real de Gemini falle y borra `GEMINI_API_KEY` y `GEMINI_MODEL` del
entorno. El juez se sustituye por un `FakeJudge` y el cliente del SDK por un
doble que devuelve objetos reales `GenerateContentResponse`. Cubren validación
de `Judgment`, ventana y redondeo, ensamblado del `Moment`, deduplicación,
recorte a 5, reintentos y errores, el prompt, la configuración y los
contadores de `GeminiJudge`.

## Errores

- `test_no_real_env_in_the_repo` (fase 0) comprobaba que `.env` no existiera
  en disco, y falla en local porque el usuario tiene un `.env` propio, ignorado
  y sin seguir. Lo que importa es que no esté bajo control de versiones, así
  que ahora comprueba con `git ls-files --error-unmatch` que `.env` no está
  seguido (y se salta si no hay git o no es un repositorio).
- Un helper de test construía el JSON de respuesta pasando por `Judgment`, que
  rechaza la categoría inválida antes de llegar al caso a probar. Se pasó a
  `json.dumps` sobre un diccionario.

## Limitaciones no verificadas

- La API real de Gemini no se ha llamado nunca. Falta comprobar que acepta el
  esquema JSON de `Judgment` (con `minLength` y `additionalProperties`) en
  `response_json_schema`, y que el nombre de modelo por defecto existe.
- Los tests solo prueban el contrato con el doble del SDK: no demuestran que
  la respuesta real tenga la forma o los contadores esperados.
- Cuota del tier gratuito: con hasta 20 candidatos y un reintento cada uno,
  un VOD puede lanzar unas 40 llamadas seguidas sin espera. Es probable que
  algunas fallen por límite de peticiones por minuto (429). Hay que decidir el
  ritmo de llamadas antes de la prueba real de la fase 4.

## Lección

Dejar el único componente que depende de un proveedor tras una interfaz y un
doble de tests permite construir y probar toda la lógica sin llamar a la API;
lo que no se puede probar así, el contrato real con el proveedor, hay que
decirlo por escrito.
